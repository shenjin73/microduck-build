## 2026-09-15 · 选飞特 HD-1910-C001 作为 XL330 的替代

**决定**：用 15 颗飞特 HD-1910-C001 替代 Dynamixel XL330-M288-T。

**为什么**：在三个候选里，它是唯一一个让结果**还是同一只鸭子**的。

| | **HD-1910-C001** ⭐ | 飞特 STS3215 | 宇树 S288 |
|---|---|---|---|
| 电压 | **4–8.4 V（2S 原生匹配）** | 7.4 V | 12.6 V（要改 3S） |
| 重量 | 21±2 g | 55–60 g | 19.5 g |
| 堵转 | 1.47 N·m @7.4V | 1.86 N·m | 0.6 N·m @12.6V |
| 机械 | 需改件 | 整机重做 | 尺寸几乎相同 |
| 净效果 | 整机 737 → ~782 g（+6%） | 变成 2.1 kg / 42 cm 的别的东西 | 供电系统重做 |

另外两条：

- ✅ **电压是优势而非妥协**：XL330 是被 Pollen 超压运行的（额定 3.7–6.0 V，实跑 6.6–8.2 V）；
  HD-1910 的 4–8.4 V **完整覆盖 2S 带载区间**，在厂商额定内工作。
- ⚠️ **电流要重算**：堵转 2.0 A vs XL330 约 1.5 A → 15 颗 **30 A** vs 22.5 A。
  官方 HAT 每个舵机接口旁注 **「3A max」**。

**数据来源（重要 —— 请连同置信度一起读）**：

这些数字**不是**来自官方仓库（官方仓库关于电机的词汇只有 `XL330` / `XL330-M288-T` / `XL330s`），
也**不是**来自厂商原始规格书。来源是第三方复刻仓库
[`fanhao375/microduck-replica`](https://github.com/fanhao375/microduck-replica) 的
`docs/硬件方案逆向.md`，它自己标注的数据源是：

> 《HD-1910-C001 串型规格书》A/0，**2026-09-07 初次发行**（厂家发给客户确认的文档，该仓库按惯例不转载 PDF）

也就是说：**这是"第三方读厂商 PDF"的结果，不是"我们读了厂商 PDF"。**

**置信度：中。** 分项：

| 项 | 置信度 | 依据 |
|---|---|---|
| 机械上要改件（压腿处） | **高** | 社区**实测** —— 他们真的装了 15 颗并重打了结构件 |
| 2.0 mm 线序与 Dynamixel 相反 | **高** | 同上，实测 |
| 过流/过压保护出厂关闭 | **高** | 社区装机记录 |
| 4–8.4 V | ⚠️ **中** | 二手解读 |
| 1.47 N·m 堵转 | ⚠️ **中** | 同上，且注明产品页保守值 10 kg·cm 曾被更正 |
| 1/320 减速比、≤0.5° 回差 | ⚠️ **中** | 同上 |

**什么会推翻它**：

- 电压区间不是 4–8.4 V → 若是 5–7.4 V，2S 满电 8.4 V 就超压了，选型的整个地基没了
- 额定负载力矩远低于预期 → **注意堵转 1.47 与额定 0.363 N·m 差 4 倍**，训练时的力矩模型用哪个是天壤之别
- 出厂运行模式不是"模式 4 纯位置 PD" → 通信层要多一层配置

**行动项**：`[ ]` 下单前向飞特索取原始规格书，自己核上面三个数。

## 2026-09-15 · 不移动三个上游 checkout

**决定**：`microduck` / `microduck-lab` / `microduck_rl` 留在原地，**不**收进 `upstream/` 子目录。

**为什么**：`microduck_local` 按**兄弟目录**找模型，是硬编码的相对路径：

```python
# walk_env.py
scene = Path(scene_xml) if scene_xml else C.SCENE_WALK_XML
if not scene.exists():
    raise FileNotFoundError("... clone microduck_rl next to microduck_local ...")
```

而 `microduck-lab` 自己的约定就是"**四个并排的 checkout**"。移动它们会直接破坏运行。

**置信度：高**（代码可查）。
**什么会推翻它**：上游改了目录约定 —— 那时跟着改。

## 2026-09-15 · 文档独立成 repo，不放进任何 clone

**决定**：路线图、决策日志、台架记录放在 `~/Projects/microduck-build/`，**不放进** `microduck` 或 `microduck-lab`。

**为什么**：

1. 它是**我们自己的项目计划**，不是任何一个上游仓库的内容
2. 它要活几个月，会不断改；放在 clone 里，每次 `git pull` 都可能冲突
3. 它要自己的历史（这份 decisions.md 的意义就在这）
4. 它**凌驾于三个仓库之上**，要同时引用它们的路径和版本
5. 台架数据、对比图、训练产物**不该提交进别人的仓库**

**置信度：高。**
**什么会推翻它**：如果决定把部分内容上游贡献，那一部分单独开分支走 PR。
